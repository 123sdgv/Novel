# Novel Chat

手机优先的中文小说写作聊天器。每个故事共享一份世界观，多个对话分别保存。页面、图标和字体全部从本地静态资源或系统提供，运行应用无需构建或后端。

## 开始写作

1. 在故事总览点击「新建故事」，为故事命名。
2. 在「设置 → 世界观」写下背景、人物和写作要求，保存。每个故事可以单独配置服务商。
3. 在「API 连接」填写兼容地址、API Key 和模型 ID。例如地址可以是 `https://api.example.com/v1`，也可以是完整的 `/chat/completions` 地址。裸域名会补上 `/v1`，自定义前缀按原样保留。可以「拉取模型」或手填。用「测试连接」发送一次极短请求，再点「保存配置」。
4. 输入写作要求，点「发送」。回车用于分段，桌面支持 Ctrl/⌘ + Enter 发送。收到正文后等待计时消失。「停止生成」保留已接收部分；如果一个字都未收到，可在该条要求下点「生成回复」重试。
5. 在消息下方编辑、复制、删除或重新生成，通过消息旁的左右按钮切换版本。顶部对话名称可用于新建、切换、改名和删除对话。
6. 点输入框旁的「总结」，检查或编辑结果，再点「新建对话并带入总结」。旧对话仍可从列表打开。

## 本地运行

在仓库目录用 Python 3 启动静态服务器。

```sh
python3 -m http.server 8000
```

浏览器打开 [本机书架](http://localhost:8000/)。ES 模块及 Service Worker 需要 HTTP(S)，请通过服务器访问。

## GitHub Pages

仓库根目录可直接发布。首次设置时，在仓库的 **Settings → Pages → Build and deployment** 选 **Deploy from a branch**。分支选 `main`，目录选 `/(root)`，点击 **Save**。这样以后提交到 `main` 的更新会自动发布。也可以选用已准备好的 `gh-pages` 发布分支；使用该分支时，需要将确认过的新版提交快进到 `gh-pages`。

此仓库的项目站点路径为 `https://123sdgv.github.io/Novel/`，以 Pages 设置中显示的发布状态为准。所有资源、启动地址、Service Worker 注册与缓存均使用相对路径。维护新版时，请同步提高 `sw.js` 中的缓存版本；关闭旧页面后重新打开即可使用新版本。

联网打开一次、待离线资源缓存完成后，可以离线查看已保存的故事、编辑和备份。生成、总结、拉取模型及测试连接均需联网。在 Android 浏览器菜单选择安装应用或添加到主屏幕，在 iOS Safari 的分享菜单中选择添加到主屏幕。

## 数据与 API

- 故事、世界观、草稿、对话树和当前选择保存在当前浏览器的 IndexedDB。API 配置独立保存。刷新或关闭后可恢复；换域名、浏览器或设备需要导入备份。清除网站数据会同时移除故事和密钥。
- 在「故事总览」导出/导入全部故事，在「故事设置」导出/导入单个故事。JSON 使用 `schemaVersion: 1`，导入会先验证全部故事，再通过一个事务创建新副本。原故事保留；即使重复导入，ID 也不会冲突。API 配置不会随备份恢复。
- API Key 以密码框输入，仅随请求发给填写的服务商，在本机浏览器中保存，未加密。GitHub Pages 同一主机下的不同项目可能同源，勿在同一源部署不受信任的脚本。Service Worker 仅缓存应用资源，跳过授权请求、API 响应和聊天内容。
- 请求首先携带固定写作指令，其次是世界观、有则附上会话的前情总结，最后才是选中分支的有效消息。重新生成在对应用户消息处截断。每组同级版本只选一个；各版本分别记住自己的后续选择。总结使用独立请求，只有确认后的总结才进入新对话。
- 小说正文默认目标约 5000 汉字，默认温度 0.8，输出预算 8192 tokens。总结的预算为 2000 tokens。上下文超过模型限制时可以总结并开新对话。服务商的上下文上限、输出上限和缓存策略决定实际效果。
- 服务商需要允许来自页面所在源的 CORS 请求，包括 Authorization 和 Content-Type。GitHub Pages 无法更改对方的 CORS 设置。网络或跨域限制、鉴权、限流、余额及接口路径错误会显示提示；部分服务商会把多种错误合并为一个状态码。可以使用支持浏览器调用的兼容接口。

## 目录

| 文件 | 职责 |
| --- | --- |
| `index.html`、`style.css`、`icons/` | 页面入口、排版与离线图标 |
| `js/app.js`、`js/view.js` | 页面导航、表单、对话交互与流式显示 |
| `js/story.js` | 消息树、版本选择、删除和请求上下文 |
| `js/db.js`、`js/backup.js` | IndexedDB 事务、版本校验、备份与恢复 |
| `js/api.js` | 兼容端点、SSE 解码、取消、超时和错误处理 |
| `manifest.webmanifest`、`sw.js` | 安装与离线缓存 |
| `tests/` | 分支、API 与浏览器验收 |

## 运行测试

需要 Node.js 22 或以上，无需安装 npm 依赖。

```sh
npm test
```

浏览器验收可在一个单独的本机端口或干净的浏览器配置中执行。启动上面的静态服务器，打开 [浏览器验收](http://localhost:8000/tests/browser.html)，点击「运行验收」。验收会在空白测试书架里写入样例，使用模拟服务商记录实际请求体、控制流的暂停与中断。它覆盖 390px 宽度、刷新恢复、编辑/重生、版本切换、总结接续、备份与离线资源。非空书架或非本机地址会拒绝运行。第三方 API 的鉴权、计费和 CORS 可在实际部署后的「测试连接」中核实。
